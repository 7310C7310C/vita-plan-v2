# OMR / 制谱核对清单

识别工具：**`lodebar2026/dolce`**（按该仓库 README 安装/运行；输出 123 初稿）。任何接手者/设备都用该工具，不写死本地路径。
制谱流程：Dolce 识别 → 本清单逐项核对 → 写入 `data/scores/*.json`。每次新谱必须逐项过一遍。

## Dolce 输出
- 只用 `lodebar2026/dolce` 的**音高/时值/歌词/和弦**作为初稿，不直接信它的视觉排版。
- 123 文本不携带 beam 分组；分组由渲染按拍处理，需对照原图确认每拍连法。
- `sustains`/圆括号/原图弧线可能表示连音线或延音；必须按原图逐条确认，写入 `slurs`/`ties`。
- 简谱的 `,`（低八度）与 `'`（高八度）逐个核对；`-` 是延长，不是休止。
- 多段歌词按原图逐字对位，注意 melisma（一字多音）与跨小节换词。

## 每谱核对
1. 小节数、拍号/变拍、每小节拍数。
2. 每个声部的音级、八度、时值、休止。
3. 每拍 beam 分组（如 3-5、5-3 两条，不是四音一条）。
4. 连音线/延音线的起止音（同音高才是 tie；不同音高是 slur）。
5. 歌词每个字的起始音/拍；特别检查小节末与下一小节首。
6. 和弦名、斜杠低音、Capo 默认值（吉他版按原调存和弦）。
7. 标题/原文/词曲/默认速度。

## 已知教训
- cl001 第 7 小节“垂”应在第 4 拍（2 音），“怜”在第 8 小节；初版把“垂/怜”放在 3/2 上，已修正。
- 和弦落在延音拍（dash）上时，和弦中心必须对齐 dash 中心：cl001 bar7 的 A、bar8 的 D。
- 曲末用结束符（细线+粗线）；只有原谱在该处有右反复记号时，才画反复点（lz019），不得默认给所有曲末加反复记号（cl001 已发生反例）。
- 行首反复在行首（含自动换行后落在行首）时：系统括号粗线 + 小节细线 + 双点即可，不必与行末对称；行内反复才用小节内粗线+细线+点的镜像样式。双点用纯黑，且伪元素宽度要容得下点，避免被裁掉。
- 复合拍每 3 个八分音一组，组内连续短音符用一条连续符槓（lz019 第 1 小节 4-3-1）；其余拍组按拍留缺口。
- 小节序号与和弦同一行并居中于小节线；不得单独占一行；拍号变更处序号让位，tag 保留。
- 普通小节线与曲末双线从音符行顶开始，不得穿过和弦行/小节序号；所有小节线用纯黑 #000。
- 歌词正文用纯黑 #000；反复双点以反复竖线的实际跨度垂直居中。
- 空拍必须写 `0`（如 jt017 首节 S/A 第 1 拍）。个别音符原谱不带八度点而音高本应带时，用事件第 6 项 `"nodot"` 抑制（如 jt017 首节 T 的 7），不要改音高。
- 单声部谱（一支谱表）不画每行左侧的系统括号；S/A/T/B 多声部保留，样式按 lz020 原谱：粗竖线 + 实心尖角弯钩（上下外扬，跨过首小节细线），不得画成细线圆角钩（cl001/cl002、旧版 lz019 样式已发生反例）。
- D.C. al Fine 与原谱 Fine 必须标在小节末端（`dc.from` 最后一小节、`dc.to` 的 Fine 小节），不得放进谱头；`check_scores.py` 强制 `dc.from` 为最后一小节。
- 单行歌词不印段号：只有同时显示 2 行以上才标 `1. 2. 3.`；主歌共用段（jt017 前 16 小节）与单段歌（cl002）都不得出现段号。
- 多段歌词若开头完全相同，原谱通常只印一行，到首次分歧才分行（jt017：前 35 音节相同，第 17 小节起 3 行）；JSON 用 `lyricCollapse:true` 自动判定分歧点，不要手写小节号，也不要把 3 段整曲重复印 3 遍。
- slur 必须逐条覆盖原图弧线：cl002 bar10 的 3–4 拍、bar17 的 2–7（跨 2-1-7）、bar21 的 5→7（“垂”字的连音），不要只按 OMR 括号猜。
- 即使用户原谱漏画/打错，也要按音乐逻辑（歌词停在 5、下一拍 7 且为同字延伸）判断连音，指出并修正；此类修正不改变用户原稿事实，但必须写进核对记录。
- jt017 第 13/14 小节“天/上”曾错位；歌词以原图逐字对位为准。
- 延音 dash 用置中线（同数字宽、3px 厚），不用字体字符；中心与音符数字对齐。
- 升降号绝对定位，不挤动数字；单声部隐藏“声部”菜单与 S 标记。
