# OMR / 制谱核对清单

工具：`lodebar2026/dolce`（使用前 `git fetch` 确认最新 tag/main，落后先 `pull --ff-only`；按该仓库 README 安装）。任何设备都用该工具，不写死本地路径。
流程：Dolce 出初稿 → 按本清单对照原图核对 → 写入 `data/scores/*.json` → 跑 `scripts/check_scores.py`。

## 工具
- Dolce 只提供音高/时值/歌词/和弦初稿；视觉排版、beam、slur/tie、歌词边界必须按原图核对。
- 123 文本不携带 beam 分组；`,`/`'` 是低/高八度，`-` 是延长不是休止。

## 核对项（逐项对照原图）
- 小节数、拍号/变拍、每小节拍数。
- 各声部音级、八度、时值、休止。
- beam 分组（按拍；复合拍每 3 个八分音一组）。
- slur/tie 起止音：同音高 tie，不同音高 slur；跨小节/跨行按原图处理。
- 歌词逐字起拍；检查小节末/下一小节首、一字多音、多段共用开头。
- 和弦名、斜杠低音、Capo；版本谱与原谱小节数/拍号/歌词/连音线一致；贝司记号随 capo 保音高换算。
- 标题/原文/词曲/默认速度。
- 谱面细节：小节序号、小节线、延音 dash、空拍/nodot、系统括号、夜间模式。
- 写完后跑 `scripts/check_scores.py`；格式、版本、资产引用由脚本校验。

## 构建
- `data/scores/**/*.json` 仍是源谱（当前运行时格式）；`data/scores/bundle.json` 由 `scripts/generate_v2_manifest.py` 生成，浏览器只下载这一份。
- 改谱后先跑 `python3 scripts/generate_v2_manifest.py`，再跑 `scripts/verify.sh`；CI 会用 `--check` 阻止忘记生成。
- bundle 是机器格式（MIDI、事件下标），不要手改；人类可编辑格式另行设计。

## 已知教训
- cl001 第 7 小节“垂”应在第 4 拍（2 音），“怜”在第 8 小节；初版把两者放在 3/2，已修正。
- cl001 bar7 的 A、bar8 的 D 落在延音拍；和弦中心必须对齐 dash 中心，初版未对齐。
- 曲末曾默认加反复点；改为曲末用结束符，只有原谱该处有右反复记号才画反复点（cl001 反例）。
- 行首反复曾与行末不对称；改为系统括号粗线 + 小节细线 + 双点，行内反复才用镜像样式（lz019）。双点用纯黑，伪元素宽度要容得下点。
- 复合拍曾逐音下划线；改为每 3 个八分音一组连成一条符槓（lz019 第 1 小节 4-3-1）。
- 小节序号曾单独占一行；改为与和弦同行、居中于小节线，拍号变更处让位、`tag` 保留。
- 小节线曾上穿和弦行/小节序号；改为从音符行顶开始，全部纯黑。
- 同一区域多条连音/延音线重叠或共用端点时，曾短上长下；改为长线在上、短线在下（bar15）。
- 跨小节 slur 曾写成同一小节；改用 6 项，跨行自动拆上下半条（16/17 T、20/21 等）。
- `bar.hum` 曾只在有哼唱的小节保留 hum 行，导致不对齐；同一条线整行保留空 hum 行。
- 空拍曾省略不写；改为写 `0`。jt017 首节 T 的 7 原谱无八度点，用 `"nodot"` 抑制显示，不要改音高。
- 单声部曾画系统括号、多声部曾画细线圆角钩；改为单声部不画，多声部按 lz020：粗竖线 + 实心尖角弯钩（cl001/cl002、旧版 lz019 反例）。
- 单行歌词曾印段号；改为只有同时显示 2 行以上才标 `1./2./3.`（jt017 主歌共用段、cl002 单段都曾反例）。
- 多段歌词曾整曲重复印 3 遍；原谱通常只印到首次分歧（jt017 前 35 音节相同，第 17 小节起 3 行），用 `lyricCollapse` 自动判定，不要手写小节号。
- cl002 bar10 的 3–4 拍、bar17 的 2–7、bar21 的 5→7 连音曾漏；slur 必须逐条覆盖原图弧线，不要只按 OMR 括号猜。
- 用户原谱漏画/打错时，不要直接照抄；按音乐逻辑判断并指出修正，写进核对记录，不擅自改源谱。
- jt017 第 13/14 小节“天/上”曾错位；歌词以原图逐字对位为准。
- 延音 dash 曾用字体字符导致不对齐；改为置中线（同数字宽、3px 厚），中心与音符数字对齐。
- 夜间模式曾硬编码黑色导致歌词不可见；改用 `--score-ink`，歌词正文纯黑。
